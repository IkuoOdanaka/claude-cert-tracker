# 開発ガイド

## セットアップ

```bash
npm install
npm run dev     # http://localhost:3000
```

### 既知のハマりどころ: Tailwind のネイティブバイナリ

npm の optional dependencies のバグ（[npm/cli#4828](https://github.com/npm/cli/issues/4828)）で
`@tailwindcss/oxide` のプラットフォーム別バイナリが入らず、ビルドが
`Cannot find native binding` で落ちることがある。

```bash
npm install --no-save @tailwindcss/oxide-darwin-arm64@$(node -p "require('./node_modules/@tailwindcss/oxide/package.json').version")
```

`node_modules` と `package-lock.json` を消してから `npm install` し直しても直る。

## スクリプト

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバー |
| `npm run build` | 静的書き出し（`out/` に出力） |
| `npm run lint` | ESLint |
| `npm run typecheck` | `tsc --noEmit` |
| `npm test` | Vitest（データ整合性テストを含む） |

CI ではこの4つ（lint / typecheck / test / build）がすべて実行される。

## Node のバージョン

**Node 22 が必要**（Next.js 16 は Node 20.9+ を要求する）。
バージョンは `.node-version` / `.nvmrc` に固定してあり、CI もこのファイルを読む。

```bash
node -v   # v22.x であること
```

### `.zshrc` で node@18 が固定されている場合

Homebrew の `/opt/homebrew/bin/node` が 22 でも、`.zshrc` に
`export PATH="/opt/homebrew/opt/node@18/bin:$PATH"` が残っていると PATH の先頭で
勝ってしまい、`npm run dev` が engines エラーで動かない。該当行を削除して
シェルを開き直す。

```bash
grep -n 'node@18' ~/.zshrc      # 該当行を確認
node -v                          # 削除後に v22.x になることを確認
```

## データを更新する

`data/*.json` は手書き。[Anthropic Partner Academy](https://anthropic-partners.skilljar.com/)
の内容が変わったら：

1. `data/certifications.json` の `meta.lastVerifiedAt` を確認日に更新する
2. 変更のあった資格・コースを直す
3. `npm test` で参照整合性を確認する
4. PR にする（何がどう変わったかを diff で残すため）

## 模擬試験の問題を追加する

`data/questions/<certificationId>.json` に追記する。**公式試験問題は使わない。**

各問に必要なもの：

- `domainId`: その資格の `examDomains[].id` のいずれか
- `correctChoiceIds`: `single` なら1つ、`multiple` なら2つ以上
- `explanation`: なぜその答えなのか
- `sourceRefs`: 根拠にした公開情報の URL（1つ以上。CI で必須チェック）

`npm test` が通れば構造は正しい。内容の正しさはレビューで担保する。

## コードの約束

### `data/*.json` は `src/lib/content.ts` からしか読まない

素の JSON を直接 import すると型が広がり(`provider: string` など)、呼び出し側の至るところで
キャストが必要になる。読み込み口を1つに保つため、`src/**` から `data/*.json` を import すると
ESLint(`no-restricted-imports`)がエラーにする。

例外は `src/lib/content.ts` 本体と `tests/`（生データそのものを検証するため）。

### `localStorage` は `src/features/progress` からしか触らない

コンポーネントが直接触ると、検証漏れとハイドレーション不整合が必ず起きる
（[ADR 0002](adr/0002-進捗データの保存先.md)）。進捗の読み書きは `useProgress()` を使う。
`src/**` から `localStorage` / `window.localStorage` を参照すると
ESLint(`no-restricted-globals` / `no-restricted-properties`)がエラーにする。

例外は `src/features/progress/storage.ts` とテストファイル。

### 進捗に依存する表示はスケルトンを挟む

進捗は `useSyncExternalStore` 経由で、マウント後に読み込まれる。
`status` が `"loading"` のあいだの `progress` は初期値なので、
**それを「進捗 0%」として描いてはいけない**。読み込み完了まではスケルトンにする。

### アクセント色と primary ボタンは「押すべきもの」専用

配色はニュートラル＋テラコッタ1色だけ。塗りつぶしのアクセント色は
**その画面で最もやってほしい操作（primary ボタン）1つ**にしか使わない。
primary を増やすと「どれを押せばいいか」が消えるので、増やしたくなったら画面の設計を疑う。

ボタンの階層は `src/components/Button.tsx` の docコメントを参照。

### 色は `globals.css` のトークンだけを使う

`text-ink` / `bg-surface` / `border-line` のように、Tailwind のテーマトークン経由で指定する。
`text-gray-500` のような素の色は使わない（ダークモードで破綻するため）。

トークンのコントラスト比は `tests/design-tokens.test.ts` が CSS を読んで検証している。
色を変えたらテストも通すこと。操作要素の輪郭には `line`（装飾用）ではなく
`line-strong`（3:1 を満たす）を使う。

### クラウド同期されるディレクトリにリポジトリを置かない

`~/Desktop` と `~/Documents` は macOS の iCloud「デスクトップと書類フォルダ」同期の
対象になりうる。同期対象のディレクトリでビルドすると、`cache-life.d 2.ts` のような
**衝突コピー**が `.next/types` に紛れ込み、型チェックが落ちる。`node_modules` 配下にも
大量に発生し、クラウドの容量と同期時間を無駄に食う。

このリポジトリは `~/Projects/claude-cert-tracker`（同期対象外）に置いている。

`tsconfig.json` の `exclude` で `**/* 2.*` を弾いてはいるが、これは保険であって解決ではない。
同期対象のディレクトリで作業しないこと。疑わしいときは:

```bash
find . -name "* 2.*" -not -path "./node_modules/*"
```

- `main` への push で CI とデプロイが走る
