# データモデル

型定義の正は [`src/types/domain.ts`](../src/types/domain.ts)。このドキュメントは
「なぜその形なのか」を補足する。

## 全体像

```
Certification ──┬── courseIds[] ──▶ Course      （推奨学習順を兼ねる）
                └── examDomains[] ──▶ ExamDomain
                                          ▲
Question ── domainId ─────────────────────┘
   └── certificationId ──▶ Certification

ProgressState（localStorage）
   ├── selectedCertificationIds[] ──▶ Certification
   ├── courses: { [courseId]: CourseProgress } ──▶ Course
   └── examAttempts[] ──▶ ExamAttempt ── answers[] ──▶ Question
```

静的コンテンツ（上半分）とユーザー進捗（下半分）は、参照は張るが**保存場所が違う**。
静的側はリポジトリの JSON、進捗側はブラウザの localStorage。

## Course

| フィールド | 意図 |
| --- | --- |
| `id` | 資格をまたいで一意。`assoc-` / `dev-` / `arch-` の接頭辞は Prep Course 固有のコース、接頭辞なしは Anthropic Academy の一般公開コース |
| `provider` | `partner-academy`（パートナー限定）か `anthropic-academy`（一般公開）か。アクセス可否が違うのでUIで区別する |
| `estimatedMinutes` | 公式に掲載がないものは `null`。「総学習時間」の表示では null を除外し、「一部未計測」と添える |
| `format` | `video` / `hands-on` / `reading`。ハンズオンは腰を据えて取り組む必要があるため区別する |

## Certification

| フィールド | 意図 |
| --- | --- |
| `courseIds` | **順序に意味がある**。公式の Prep Course の並び順 = 推奨学習順 |
| `examDomains` | 模擬試験の出題配分と、結果画面の弱点分析の軸 |
| `domainsSource` | `derived-from-prep-courses` は「公式の出題範囲表ではなく Prep Course の構成から推定した」ことの明示。UI 上でも注記する |
| `notes` | 「Associate はティア要件にカウントされない」など、資格選択の判断材料になる公式記載 |

`examDomains[].weight` は現在すべて未設定（= 均等配分）。公式の配点が公開されたら設定する。

## Question

出典なしの問題を作らないことを構造で強制するため、`sourceRefs` は必須配列。
CI（`tests/data-integrity.test.ts`）で空配列を弾く。

`difficulty` は 1〜3。将来「難易度を上げて再挑戦」を実装するときの軸として先に持っておく。

## ProgressState（localStorage）

保存キー: `cct:progress`

```jsonc
{
  "version": 1,                       // スキーマ変更時のマイグレーション用
  "selectedCertificationIds": ["claude-certified-developer-foundations"],
  "courses": {
    "dev-mso-foundations": {
      "status": "completed",
      "completedAt": "2026-08-25T04:00:00.000Z",
      "note": "MSO の位置づけを再確認"
    }
  },
  "examAttempts": [ /* ExamAttempt[] */ ],
  "updatedAt": "2026-08-25T04:00:00.000Z"
}
```

### 設計上の約束

- **読み込みは必ず検証を通す**。localStorage の中身はユーザーが編集できるし、
  古いスキーマのまま残ることもある。パースに失敗したら初期状態にフォールバックし、
  ユーザーに「進捗を復元できませんでした」と伝える（黙って消さない）。
- **存在しない ID を許容する**。`data/*.json` からコースが消えても進捗側に ID が残りうる。
  表示時に解決できなかった ID は無視するが、保存データからは消さない
  （データ側が戻れば復活するように）。
- **書き込みは進捗レイヤーの1関数に集約**。コンポーネントから直接 localStorage を触らない。

## データの更新運用

`data/*.json` は手書き。公式サイトが変わったら以下を更新する：

1. `data/certifications.json` の `meta.lastVerifiedAt` を確認日に更新
2. 変更のあった資格・コースを修正
3. `npm test` で整合性テストを通す
4. PR にして、何が変わったかを diff で残す
