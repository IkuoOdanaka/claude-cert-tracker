# 全体設計

## 1. このアプリは何か

Anthropic の Claude 認定資格（Claude Certified Associate / Developer / Architect）を
取りたい人が、**「どの資格を取るか決める → 必要なコースを把握する → 消化状況を記録する →
模擬試験で仕上げる」** までを 1 画面で完結できるようにする学習トラッカー。

Anthropic 非公式の個人プロジェクト。公式の学習コンテンツそのものは提供せず、
公式ページ（[Anthropic Partner Academy](https://anthropic-partners.skilljar.com/)）への
導線と、自分の進捗の記録に徹する。

### 解きたい課題

| 課題 | このアプリでの解決 |
| --- | --- |
| 資格が4種類あり、どれを目指すべきか分かりにくい | 対象者・価格・所要時間で比較できる資格選択画面 |
| 各資格の Prep Course が公式サイト上で分散している | 資格ごとに推奨学習順で1リストに束ねる |
| Skilljar 側の完了状態を横断で俯瞰できない | コース単位のチェックと進捗バー・残り時間の可視化 |
| 受験前の実力確認ができない | 出題範囲（ドメイン）別のオリジナル模擬試験 |

### やらないこと（スコープ外）

- 公式試験問題の転載・再現。模擬試験は**すべてオリジナル問題**とし、各問に出典（根拠にした公開情報）を持たせる。
- Skilljar アカウントとの連携・自動同期。ログイン情報は一切扱わない。
- 学習コンテンツ（動画・教材）そのものの提供。

## 2. アーキテクチャ

```
                 ┌──────────────────────────────┐
   ビルド時       │  data/*.json (手動メンテ)      │
   （GitHub      │   certifications.json          │
    Actions）    │   courses.json                 │
                 │   questions/<certId>.json      │
                 └──────────────┬───────────────┘
                                │ import（型付け + CI で整合性検証）
                                ▼
                 ┌──────────────────────────────┐
                 │  Next.js 15 App Router        │
                 │  output: "export"（SSG）      │
                 └──────────────┬───────────────┘
                                │ 静的ファイル一式 (out/)
                                ▼
                 ┌──────────────────────────────┐
   実行時         │  GitHub Pages（静的配信のみ）  │
                 └──────────────┬───────────────┘
                                │
                                ▼
                 ┌──────────────────────────────┐
                 │  ブラウザ                      │
                 │   localStorage: 進捗・受験履歴  │
                 └──────────────────────────────┘
```

**サーバーを持たない**のが最大の設計判断。学習コンテンツは静的データ、進捗は各自のブラウザ内。
これにより認証・DB・個人情報の保管がすべて不要になり、URL を配るだけで誰でも使える。
代償は「端末をまたいだ同期ができない」こと。これは JSON のエクスポート／インポートで補う。

詳細な判断理由は [adr/0001-技術選定.md](adr/0001-技術選定.md)、
[adr/0002-進捗データの保存先.md](adr/0002-進捗データの保存先.md) を参照。

## 3. ディレクトリ構成

```
claude-cert-tracker/
├── data/                        # 静的コンテンツ（手動メンテ、PR でレビュー）
│   ├── certifications.json      # 資格 → コース・出題ドメインの対応
│   ├── courses.json             # コースのマスタ
│   └── questions/               # 資格ごとのオリジナル問題バンク
│       └── <certificationId>.json
├── docs/                        # 設計ドキュメント
│   └── adr/                     # アーキテクチャ決定記録
├── src/
│   ├── app/                     # App Router（画面）
│   ├── components/              # UI コンポーネント
│   ├── features/                # 機能単位のロジック（progress / exam など）
│   ├── lib/                     # データ読み込み・純粋関数
│   └── types/domain.ts          # ドメイン型の単一の置き場所
├── tests/                       # データ整合性テストなど
└── .github/workflows/           # CI（lint/型/テスト/build）と Pages デプロイ
```

`src/lib` と `src/features` のロジックは**副作用のない純粋関数**を基本とし、
localStorage へのアクセスは `features/progress` の 1 レイヤーに閉じ込める。
テストしやすさと、将来サーバー同期を足すときの差し替えやすさのため。

## 4. 画面構成

| # | 画面 | パス | 役割 |
| --- | --- | --- | --- |
| 1 | 資格を選ぶ | `/` | 4資格をカードで比較。対象者・価格・総学習時間・進捗率を表示し、目標として選択できる |
| 2 | 学習ロードマップ | `/certifications/[id]` | 選んだ資格の推奨学習順コース一覧。各コースをチェックして完了記録。進捗バーと残り時間 |
| 3 | ダッシュボード | `/dashboard` | 目標にした資格を横断した進捗、直近の学習記録、模擬試験のスコア推移 |
| 4 | 模擬試験（設定） | `/exam/[certId]` | 出題数・ドメイン絞り込み・時間制限の有無を決めて開始 |
| 5 | 模擬試験（受験） | `/exam/[certId]/run` | 1問1画面。前後移動・フラグ付け・残り時間表示 |
| 6 | 模擬試験（結果） | `/exam/[certId]/result` | 総合スコアとドメイン別スコア、間違えた問題の解説と出典、弱点ドメインに対応するコースへの導線 |
| 7 | 設定 | `/settings` | 進捗の JSON エクスポート／インポート、全消去 |
| 8 | このサイトについて | `/about` | 非公式である旨の明示、データの出所、更新日、問題の作成方針 |

**画面2 → 画面6 → 画面2 のループ**（学ぶ → 測る → 弱点に戻る）がこのアプリの中心動線。
結果画面からドメイン別の弱点に対応するコースへ直接飛べることを重視する。

## 5. データモデル

型の正は [`src/types/domain.ts`](../src/types/domain.ts)。概要は
[データモデル.md](データモデル.md) を参照。

要点：

- **静的コンテンツ**（`Certification` / `Course` / `Question`）と
  **ユーザー進捗**（`ProgressState`）を型レベルで完全に分離する。
- `Certification.courseIds` は**推奨学習順**を兼ねる配列。順序に意味がある。
- `Certification.examDomains` は現時点では公式の出題範囲表ではなく
  **Prep Course のモジュール構成から導出**したもの。`domainsSource` フィールドで
  それを明示し、公式の範囲表が公開されたら `"official"` に切り替える。
- `ProgressState.version` を持たせ、スキーマ変更時に localStorage をマイグレーションできるようにする。

## 6. 模擬試験の設計

### 問題の作り方（重要な制約）

公式試験問題は使わない。すべてオリジナル問題とし、`Question.sourceRefs` に
**根拠にした公開情報の URL** を必ず持たせる。CI でこのフィールドの存在を検証する。

### 出題ロジック

1. 指定された資格の問題バンクを読み込む
2. ドメイン絞り込みが指定されていれば絞る
3. `examDomains[].weight` があればその比率で、なければ均等にドメインから配分
4. 各ドメイン内でシャッフルして必要数を取り出す
5. 選択肢の並びもシャッフルする（正解の位置を覚えてしまうのを防ぐ）

出題は**シード付き擬似乱数**で行い、同じシードで同じ問題セットを再現できるようにする。
「前回と同じセットでもう一度」「間違えた問題だけ再挑戦」を実現するため。

### 採点

- 単一選択：完全一致で正解
- 複数選択：**部分点なし**の完全一致。実際の認定試験の一般的な採点に寄せる
- ドメイン別の正答率を出し、弱点ドメイン → 該当コースへの導線に使う

## 7. 品質の担保

| 対象 | 方法 |
| --- | --- |
| データの壊れ（存在しないコース ID、選択肢にない正解など） | `tests/data-integrity.test.ts` で CI ブロック |
| 型 | `npm run typecheck`（`tsc --noEmit`）を CI で実行 |
| 出題・採点ロジック | 純粋関数として切り出し、ユニットテスト |
| 画面 | 主要な操作フローに絞ったコンポーネントテスト（Phase 2 以降） |
| アクセシビリティ | キーボード操作のみで模擬試験を完走できることを受け入れ条件に含める |

## 8. 制約と既知の課題

- **Node 18 前提**：ローカルの Node が 18.20.8 のため Next.js は 15 系に固定している。
  Node 20+ に上げれば Next 16 系に移行可能（Issue 化済み）。
- **npm audit の high 3件**：いずれも Next.js が内包する postcss / sharp の脆弱性。
  静的書き出しのビルド時にしか使われず、配信される成果物には含まれない。
  `npm audit fix --force` は Next を 9 系に落とすため実行しない。Next のアップデートで解消を待つ。
- **公式サイトの変更追随**：`data/certifications.json` の `meta.lastVerifiedAt` に
  最終確認日を持たせている。定期的に公式サイトと突き合わせて更新する運用が必要。
