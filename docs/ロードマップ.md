# ロードマップ

タスクの正は [GitHub Issues](https://github.com/IkuoOdanaka/claude-cert-tracker/issues)。
このドキュメントは「なぜこの順番なのか」を示す。

## 優先順位の考え方

**「資格を選んで、やることが見えて、消化を記録できる」までを最短で使える状態にする。**
模擬試験は価値が高いが、問題を作るコストが大きく、学習トラッカーとしての土台がないと
戻り先（弱点 → コース）が存在しない。だから土台が先。

M1 公開後は、**実際に使った人の「実感が持てない」に応えること**を優先した。
資格単位の模擬試験より、コース単位の理解度チェックのほうが学習のループが短い。

ラベル `P0` > `P1` > `P2` の順に着手する。

## マイルストーン

### M0: 基盤（完了）

リポジトリ・静的書き出し設定・CI・Pages デプロイ・データスキーマ・整合性テストまで。
`npm run lint / typecheck / test / build` がすべて通る状態。

実装に入る前に **Node 22 / Next.js 16 への移行**も済ませた
（[ADR 0003](adr/0003-Node22とNext16を前提にする.md)）。当初は M3 に置いていたが、
Node 18 が EOL であること、移行コストは画面を作る前の今が最小であることから前倒しした。

### M1: MVP — 学習トラッカーとして使える（P0）

ここまでで「公式サイトを何度も行き来しなくても、自分がどこまで進んだか分かる」状態になる。

- データ読み込みレイヤーと進捗レイヤー（localStorage）
- 資格選択 → 学習ロードマップ → 完了記録 → ダッシュボード
- 進捗の JSON エクスポート／インポート（[ADR 0002](adr/0002-進捗データの保存先.md) の約束）
- About 画面での非公式表記
- GitHub Pages での公開

**M1 の完了条件**: 他人に URL を渡して「使ってみて」と言える。

### M2: 理解度チェック（P0）

公開後のフィードバックで方針を変えた。**「基本が動画セッションなので、理解できたという
実感を持ちにくい。セッションごとの理解度テストが欲しい」**。当初の M2 は資格単位の模擬試験
だったが、欲しいのはコースを1本見終わった直後の小さなテストで、粒度が違う。

- 問題データにコースの紐づけ（`courseIds`）を追加
- 出題エンジン（コース／ドメイン絞り込み・シード付き乱数・シャッフル・採点）
- コース行からの理解度チェック（3〜5問 → 結果 → コース行に「理解度 4/5」）
- オリジナル問題を**コースごとに** 3 問以上。まず Associate の 8 コース

決めたこと:
- **結果は参考表示のみ。完了は本人が決める。** テストは動画の内容そのものを問えないので
  （開発者が動画を見られない）、ゲートにするのは強すぎる
- 資格単位の模擬試験は M3 へ。同じ問題バンク・同じエンジンで動くので薄い画面を足すだけ

**M2 の完了条件**: Associate の 8 コースすべてで理解度チェックが受けられ、結果がコース行に残る。

### M3: 資格単位の模擬試験（P1）

学ぶ → 測る → 弱点に戻る、のループを資格全体で閉じる。

- 設定 → 受験 → 結果 の3画面
- 受験履歴とスコア推移
- 残り3資格のコースぶんの問題

**M3 の完了条件**: 4資格すべてで模擬試験を通しで受けられ、結果から弱点コースへ飛べる。

### M4: 磨き込み（P2）

- アクセシビリティ（キーボードのみで模擬試験を完走できる）
- 公式サイトとのデータ突き合わせを定期運用にする
- 問題数の拡充、難易度別の再挑戦
