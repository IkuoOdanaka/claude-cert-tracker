# ADR 0001: Next.js 15 + 静的書き出し + GitHub Pages

- ステータス: 承認（一部を [ADR 0003](0003-Node22とNext16を前提にする.md) が置き換え）
- 日付: 2026-08-25

> [!NOTE]
> 「なぜ Next 15 系に固定するのか」の判断は [ADR 0003](0003-Node22とNext16を前提にする.md) で覆した。
> Node 18 が EOL であること、移行コストが今が最小であることを踏まえ、Node 22 / Next 16 に移行済み。
> **Next.js + 静的書き出し + GitHub Pages という中核の決定はそのまま有効。**

## コンテキスト

Claude 認定資格の学習トラッカーを作る。要件として決まっていること：

- **誰でも URL を開けば使える**ようにしたい（KAG 社内・社外の学習者に配れる）
- 進捗を記録できる
- 模擬試験を実施できる
- ある程度の規模の開発になる想定で、段階的に育てられる構成にしたい

制約：

- ローカルの Node は 18.20.8
- 運用コストは極力ゼロにしたい（個人の副業プロジェクトであり、サーバー費用と保守は避けたい）

## 決定

**Next.js 15（App Router / TypeScript / Tailwind CSS v4）を `output: "export"` で静的書き出しし、
GitHub Pages で配信する。バックエンドは持たない。**

## 理由

### なぜバックエンドを持たないのか

学習進捗は「本人が自分の学習を管理する」ためのデータで、他人と共有する必然性がない。
サーバーを持つと、認証・DB・個人情報の保管責任・運用費が一気に発生する。
これらは今回のプロダクト価値（資格取得の道筋が見えること）にほとんど寄与しない。

進捗をブラウザに置くことで、URL を配るだけで誰でも使える状態が最小コストで成立する。

### なぜ Next.js か（Vite + React ではなく）

- **将来サーバーが必要になったときに移行できる**。「複数端末で同期したい」「チームの進捗を
  見たい」という要求が出たら、静的書き出しをやめて Route Handlers / Server Components に
  移せる。Vite の SPA からだとフレームワーク移行になる。
- ファイルベースのルーティングが、資格ごと・試験ステップごとに画面が増えていく今回の構造に合う。
- ビルド時のデータ読み込み（`data/*.json` を import して静的生成）が素直に書ける。

### なぜ Next 15 系に固定するのか

Next 16 系は Node 20.9+ を要求する。ローカルの Node が 18.20.8 なので、
Node を上げずに始められる 15 系（Node 18.18+ 対応）を選ぶ。
CI とデプロイは Node 22 で回すため、Node を上げるのはローカル都合だけの話であり、
後から移行できる（Issue 化済み）。

## 結果

### 得られるもの

- ホスティング費用ゼロ、サーバー保守ゼロ
- 認証なし、個人情報の保管なし → プライバシー面の説明が単純
- push するだけでデプロイされる

### 引き受けるトレードオフ

| トレードオフ | 対処 |
| --- | --- |
| 端末をまたいだ進捗同期ができない | 進捗の JSON エクスポート／インポート機能を用意する |
| ブラウザのデータを消すと進捗も消える | 同上。加えて設定画面で警告を出す |
| コースデータの更新にデプロイが必要 | 更新頻度は低い（公式サイトの改定時のみ）。PR で差分をレビューできる利点のほうが大きい |
| GitHub Pages のプロジェクトサイトはサブパス配信 | `basePath` を CI から環境変数で渡す。ローカル開発では空文字 |

## 却下した案

- **Vite + React の SPA**：軽量だが、将来サーバーを足す道が細い。今回は「ある程度の規模に
  育てる」前提があるため、拡張余地を優先した。
- **Supabase 等でクラウド + ログイン**：チーム進捗の共有はできるが、認証・DB・運用コストが
  今の価値に見合わない。要求が出てから移行する。
