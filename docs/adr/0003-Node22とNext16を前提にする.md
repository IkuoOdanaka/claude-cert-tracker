# ADR 0003: Node 22 / Next.js 16 を前提にする

- ステータス: 承認
- 日付: 2026-08-25
- 関連: [ADR 0001](0001-技術選定.md) のバージョン固定に関する部分を置き換える

## コンテキスト

[ADR 0001](0001-技術選定.md) では、開発機の Node が 18.20.8 だったことを理由に
Next.js を 15 系（Node 18.18+ 対応）に固定した。Next 16 系は Node 20.9+ を要求するためである。

しかしこの判断には見落としがあった。

- **Node 18 は 2025年4月に EOL を迎えている。** 新規プロジェクトを EOL のランタイム前提で
  始めるのは、セキュリティ更新を受けられない状態を自ら選ぶことになる。
- **`npm audit` の high 3件（postcss / sharp）は Next 15 が内包するもの**で、
  Next を上げない限り解消しない。「ビルド時にしか使われないから」と先送りしていた。
- **移行コストは時間とともに増える。** 画面もロジックもまだ無いこの時点が最小点であり、
  M1 の9画面を作ってから上げると、影響範囲の確認だけで独立した作業になる。
- 開発機の Node 18 は `.zshrc` で PATH の先頭に固定されていただけで、
  Homebrew の `/opt/homebrew/bin/node` はすでに 22.22.0 にリンクされていた。
  つまり「Node を上げられない」という前提自体が誤りだった。

## 決定

**Node 22 / Next.js 16 を前提にする。** バージョンは `.node-version` に固定し、
ローカルと CI で同じものを使う。

## 変更したこと

| 対象 | 変更 |
| --- | --- |
| Node | 18.20.8 → 22.22.0（`.node-version` / `.nvmrc` で固定） |
| Next.js | 15.5.23 → 16.3.2 |
| React | 19.1.0 → 19.2.x |
| `package.json` の `engines` | `>=18.18` → `>=20.9.0` |
| CI | `node-version: 22` の直書き → `node-version-file: .node-version` |
| ESLint 設定 | `FlatCompat` 経由をやめ、flat config を直接読む形に書き換え |
| `tsconfig.json` | `jsx: preserve` → `react-jsx`（Next 16 の必須変更） |
| `@eslint/eslintrc` | 不要になったため削除 |

### ESLint 設定の書き換えについて

`eslint-config-next` 16 は flat config をそのまま export するようになった。
create-next-app 15 が生成する `@eslint/eslintrc` の `FlatCompat` 経由の読み込みは、
16 系の設定に対しては循環参照でクラッシュする（`eslint` がエラーすら出せずに落ちる）。

`eslint-config-next/core-web-vitals` と `eslint-config-next/typescript` を
直接 import する形に書き換えた。

## 結果

- `npm audit` の脆弱性が **0件** になった
- サポート中のランタイムの上で開発できる
- `.node-version` により、ローカルと CI のバージョンがずれない

### 引き受けるトレードオフ

- 開発機の `.zshrc` で node@18 を PATH の先頭に固定している場合、外す必要がある。
  外さないと Next 16 が engines エラーで動かない。詳細は
  [開発ガイド.md](../開発ガイド.md) を参照。

## 却下した案

- **Next 15 のまま進め、M3 で移行する**（当初の計画）。移行コストが画面の増加に比例して
  増えること、EOL ランタイムと既知の脆弱性を抱えたまま開発を続けることの両方が受け入れがたい。
