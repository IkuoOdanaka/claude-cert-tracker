# ADR 0002: 進捗データは localStorage に置き、JSON で持ち出せるようにする

- ステータス: 承認
- 日付: 2026-08-25

## コンテキスト

[ADR 0001](0001-技術選定.md) でバックエンドを持たないと決めた。
では学習進捗（コースの完了状態、模擬試験の受験履歴）をどこに置くか。

ブラウザ内の選択肢は主に localStorage と IndexedDB。

## 決定

**localStorage に単一の JSON として保存する（キー: `cct:progress`）。
加えて、その JSON をファイルとしてエクスポート／インポートできるようにする。**

## 理由

### なぜ IndexedDB ではなく localStorage か

保存するデータが小さい。コース数は全資格合わせて25、模擬試験の履歴も1件あたり数 KB。
localStorage の 5MB 制限に対して十分な余裕がある。

IndexedDB は非同期 API のぶんコードが増え、初期化・トランザクション・スキーマ更新の
扱いが必要になる。今の規模では複雑さに見合わない。
受験履歴が肥大して問題になったら、そのとき移行する（`ProgressState.version` があるので
マイグレーションの筋道はある）。

### なぜ単一 JSON か

キーを分割すると「一部だけ更新に成功して不整合が残る」状態が起きうる。
単一 JSON なら読み書きが常にアトミックになり、エクスポート／インポートもそのまま実装できる。

### なぜエクスポート／インポートが必須なのか

localStorage は「ブラウザのデータを消す」操作で消える。仕事用 PC と個人 PC で
学習を進めるケースもある。**進捗が消える／持ち運べないことは、このアプリを使い続けない
理由として十分に強い**ため、代替手段は最初のリリースに含める。

## 結果

- 進捗レイヤー（`src/features/progress`）が localStorage への唯一の窓口になる。
  コンポーネントは `localStorage` を直接触らない。
- 読み込み時は必ず検証を通し、失敗したら初期状態にフォールバックしたうえで
  **ユーザーに明示的に伝える**（黙って消さない）。
- SSR / 静的書き出し時に `window` は存在しない。進捗の読み込みは必ずマウント後に行い、
  初回レンダリングはサーバーとクライアントで同じ結果になるようにする
  （ハイドレーション不整合を避けるため、進捗表示部分は読み込み完了までスケルトンにする）。

## 却下した案

- **URL にエンコードして共有**：進捗が長くなると URL 長の限界に当たる。共有要求も現時点でない。
- **GitHub Gist に保存**：認証が必要になり、バックエンドなしの利点を失う。
